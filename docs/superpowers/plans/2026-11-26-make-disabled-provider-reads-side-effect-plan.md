# Make Disabled-Provider Reads Side-Effect Free Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `DisabledClientsManager.isDisabled()` a pure read that treats a malformed marker as zero, and remove the second disabled check from `BaseApiClient.fetch()` so a lookup consults the marker once, through `ApiClientManager`'s `getStatus()` gate.

**Architecture:** `isDisabled()` is reduced to one comparison over a private `#disabledUntil()` reader that parses `fm_disabled_<source>` and maps absent, non-string, and non-numeric values to `0`; nothing is written. `BaseApiClient.fetch()` loses its leading `#isDisabled()` check, leaving `getStatus()` as the only caller of that helper and the manager gate as the only disabled read per lookup. `src/core/api-manager.ts` is not modified.

**Tech Stack:** TypeScript (ES2022, ESM), Vitest 5 with jsdom, Rollup, ESLint, Prettier, Node.js 24.x.

**Spec:** `docs/superpowers/specs/2026-11-26-make-disabled-provider-reads-side-effect-design.md`

## Review Focus

- A shipped marker that is a boolean rather than a string: it must read as healthy and must keep the non-string branch of the new reader covered. Pinned by the boolean row of Task 2's `it.each`.
- A corrupted marker such as `'abc'` or `'Infinity'`: the provider must become usable again without a manual reset. Pinned by the malformed rows of Task 2's `it.each`.
- An expired marker: the read must perform no storage write at all. Pinned by `expect(mockAdapter.storageSet).not.toHaveBeenCalled()` on every row of Task 2's `it.each`.
- An ungated `fetch()` call on a disabled provider: it proceeds, because the client no longer checks, and only `getStatus()` can stop it. Pinned by `performs no disabled check of its own` in Task 3.
- One lookup, one health check: the manager must call `getStatus()` exactly once. Pinned by `checks provider health once per lookup` in Task 3.

Deliberately not pinned: the one-millisecond boundary where `expiry === Date.now()` reads healthy. Spec Decision 10 accepts this, so reviewers check that the comparison stays `>` rather than `>=`.

- [ ] **Step 3: Implement the pure read**

In `src/core/disabled-clients.ts`, reduce the method to one comparison and add the private reader directly after it:

- `#disabledUntil(source: ApiSourceType): Promise<number>` reads `await this.#adapter.storageGet(this.#key(source))`, returns `0` when the value is not a string, otherwise `Number.parseInt(value, 10)`, and returns `0` when that result is `NaN`. It takes no JSDoc.

- Replace the `isDisabled()` JSDoc with copy that states the read-only contract and the healthy inputs:

```ts
/**
 * Reports whether an API client is currently disabled due to recent failures.
 *
 * This is a read-only check: it never writes to storage. A marker that is
 * absent, `'0'`, non-string, non-numeric, or already expired reads as not
 * disabled.
 *
 * @param source - The API provider identifier (e.g., 'xmdb', 'omdb').
 * @returns True when the source's lockout has not expired, false otherwise.
 */
```

Use exactly `Number.parseInt(value, 10)` plus `Number.isNaN`, matching `RequestQueue#getLastGlobalRequestTime` (`src/core/request-queue.ts:103`). Do not use `Number(value)`.
